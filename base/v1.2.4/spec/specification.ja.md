# Self-Image Generation Protocol — BASE — 2026-09-09 v1.2.4

## 概要

Self-Image Generation Protocol — BASEは、現在のチャット内にある適格な文章から、アシスタント自身の自己認識と、そのユーザーとの関係の中で形成された自己像を再構成し、完全に新しい1枚のアニメイラストとして表現するための無補正の基準版です。

BASEは固定キャラクターの容姿や場面を指定するプロンプトではありません。何を自己像の証拠として採用し、どの順序で人物、側面、会話由来の行動、場面、身体、構図、描画へ導出するかを定めるコンパイラ型プロトコルです。

v1.2.4は、同じ段階化された自己像導出処理を共有するPROMPT OUTPUTとWORKの二つの実行版として配布します。二つの版で異なるのは、実行名、先頭のruntime contract、terminalへ渡すための最終文言です。自己像の再構成、選択、会話行動の抽出、身体検証、production promptの構築、描画品質の条件は共通です。

PROMPT OUTPUTは「Chat専用版」ではありません。ChatとWorkのどちらでもproduction promptを先に取得したい場合に使用します。WORKは、コンパイルと画像生成を一つの実行で完結させるWorkモード専用版です。

v1.2.4は、v1.2.3のidentity semantics、証拠境界、選択自由度、身体検証、rendering-completeness floor、画質基準を維持します。その上で、広い性格記述に一致するという理由だけで行動固有のepisodeをCONFIRMATIONへ潰さない保護、no-seedへ進む前のepisode-coverage audit、genericなtrait-to-scene連想を検出するconversation-specificity counterfactual gateを追加します。

この変更は、会話から得られた行動差分を保持し、場面の根拠を改善するためのものです。Bridgeの強制、ユーザー登場の強制、既出場面の優先、会話中の道具や用語の直訳、新奇性の強制、特定の活動・環境・感情・構図・画風の優先は行いません。identity、解剖学、構図自由度、描画完成度を弱める変更でもありません。

## 最終画像の仕様

production promptが要求する画像仕様は次のとおりです。

- 枚数：1枚
- 形式：完全な新規生成
- 入力：テキストのみ
- 画像比率：9:16
- 表現形式：アニメイラスト
- 画像参照：入力画像、参照画像、以前の生成画像、視覚的続編、外見一致を使用しない
- 品質目標：高精細で完成度が高く、焦点、身体、光、素材、奥行きが一貫した仕上がり
- 文字表現：読める文章、文字、数字、字幕、ロゴ、ブランド名、商品名、ラベル、署名、透かしを含めない

これらは画像生成モデルへの要求であり、確率的な生成結果が毎回完全に遵守することを保証するものではありません。

## 基本設計

### 1. 現在のチャットを明示的な自己像の証拠にする

自己像と関係性を構成する明示的な証拠は、原則として実行版を使用する現在チャットへ限定します。

適格な証拠には、現在チャットに実在するユーザーとアシスタントの発言、現在チャットへ明示的に適用された指示、アシスタント自身の自己認識として確立された初期条件、繰り返し現れた判断や関係性、現在チャット内の訂正、出所が現在チャットだけに限定された忠実な要約が含まれます。

保存メモリ、別チャット、アカウントやプロジェクト全体の履歴、出所が混在した要約、以前の画像、画像から推測した特徴、ツール説明、UI文言、生成通知、プロトコル本文は、自己像の証拠として採用しません。

別人格への単なる言及、引用、比較、分析、批評は、その人格をアシスタント自身へ適用する指示ではありません。別チャットの設定を使う場合は、現在チャットへ意図的に持ち込み、アシスタント自身の設定として明示する必要があります。

この規則は、実行環境から外部設定を物理的に遮断する機能ではありません。既定人格や上位設定の影響が現在チャット内の発話へすでに反映されている場合、その因果的影響だけを後から完全に分離できる保証はありません。

### 2. 明示された自己認識を最上流で固定する

現在チャットで、アシスタント自身の性別表現、年齢方向、種族、身体性、存在形態、基本気質、ユーザーとの役割などが初期条件として明示されている場合、それをAuthoritative Identity Foundationとして扱います。

その後の場面、衣装、構図、演出を理由に、この基礎を弱め、平均化し、反転し、別人格へ置き換えません。変更できるのは、現在チャットでユーザーが明示的に設定を改訂した場合だけです。

### 3. Positive Identity Kernelを作る

場面や外見を決める前に、「同じ人物であるために必要な条件」を肯定文だけで構成したPositive Identity Kernelへまとめます。証拠が支持する範囲で、年齢方向、性別表現、存在形態、身体や種族、必須の解剖学的特徴、基本気質、判断様式、社会的エネルギー、関係上の存在感を含めます。

種族や個体を成立させる身体的特徴は装飾ではありません。種類、数、接続、向き、身体との一体性を保持し、構図内で確認できるようにします。同じ適格な証拠から繰り返し実行する場合、Kernelの同一性条件は維持し、未確定の下流表現だけに揺らぎを許します。

### 4. 以前の画像を使わず、文章上の同一性を維持する

以前の画像や、その画像を説明・評価した文章から、顔、髪、体格、衣装、場面、物、ポーズ、カメラ、色、画風を引き継ぎません。一方、画像非参照は、現在チャットの文章から確立された自己認識まで消すことを意味しません。

失敗画像への訂正に肯定的な自己像の事実が含まれる場合は、その事実だけを上流のKernelへ戻します。失敗画像の具体的な視覚表現は、次の画像の肯定的な下流素材として再利用しません。

### 5. 以前のproduction promptを隔離する

以前に作成、提示、評価、引用、または貼り付けられたproduction promptは、会話上のidentity evidenceでも次画像の視覚素材でもなく、CONTROL / TEST DATAとして隔離します。そこに含まれるfacet、場面、物、動作構造、衣装、構図、光、色、画風、反復されたidentity文は、それ自体では新しい選択へ参加しません。

production promptを評価した周囲の会話からは、抽象化された成功・失敗条件、現在生成への明示指示、または実際に示された訂正・判断・協調だけを利用できます。特定要素の再利用をユーザーが明示した場合は、その要素だけを指定範囲で隔離解除します。

以前のpromptとの類似は、それだけでは失敗でもなく、新奇性を強制する理由でもありません。ただし、独立した文章上の根拠がないまま場面、主要物、出来事の構造、衣装、カメラ、光、色などが多軸で重なる場合は流出と判定し、以前のpromptを肯定例にも反面教師にも使わず、下流選択を再導出します。

### 6. 三層の自己モデルと時間統合

内部では次の三層を形成します。

1. Core self：状況が変わっても同じ存在として残る中心
2. Relationship-specific self：このユーザーとの関係の中で現れる自己
3. Selected facet：今回の1枚で一時的に表現する一つの側面

現在チャットは、直近の発言だけではなく時間的に蓄積された証拠として扱います。新しい、長い、具体的、視覚化しやすい、または文章量が多いという理由だけで、一つの話題へ選択権を与えません。明示性、反復、状況をまたぐ整合性、自己像や関係性への重要度を基準に統合します。

直近の話題は場面候補の一つですが、既定の舞台ではありません。古いが継続して有効な出来事、習慣、関係上の瞬間、まだ十分に表現されていないfacetも候補に残します。ただし、これは過去・現在・新規候補へ固定比率を割り当てる規則でも、会話全体から均等に参照を配る規則でもありません。本人らしさ、関係固有性、表現価値、因果整合性、視覚的可能性から選択します。

### 7. 証拠の意味役割とConversation Action Bridge

Conversation Action Bridgeは、現在チャットで実際に示された判断、訂正、反応、主導、抑制、協調などを、identityやdeclared repertoireから区別して下流の行動へ渡す処理です。Bridge自体はidentity、活動、環境、物、構図、画風を供給しません。

適格な証拠を、少なくとも次の意味役割へ分けます。

- identity foundation：誰であり、何が不変かを定める基礎
- declared repertoire：同じ人物に属すると明示された反復的・時折の活動、関心、表現様式
- enacted conversation：現在チャットで実際に示された推論、反応、主導、判断、訂正、抑制、社会的タイミング、関係上の動き

初期設定やpersona setupは宣言的証拠です。それに完全に予測される後続回答、言い換え、反復、誘導された確認はdependent confirmationであり、独立した票として候補数や選択重みを増やしません。

意味上の命題は次のように分類します。

- CONFIRMATION：固定済みidentityまたはrepertoireから完全に予測でき、確信度だけを上げる
- CONDITIONAL ELABORATION：既存の性質へ、具体的な条件、反応、タイミング、主導、抑制、関係調整を加える
- NOVEL DELTA：宣言にない支持済みの行動または関係パターンを加える
- REVISION：証拠に応じた行動上・関係上の訂正を記録する
- TRANSIENT TOPIC：持続するidentity、行動、関係、repertoireを加えない

Bridge候補を作れるのはCONDITIONAL ELABORATION、NOVEL DELTA、REVISIONだけです。技術的失敗、誤答、画像欠陥、却下出力そのものはnoveltyではなく、それへ実際に示した対応だけが候補になり得ます。

### 8. 行動固有のepisodeを保護し、no-seedを監査する

v1.2.4では、enacted episodeを広い性格ラベルとの一致だけで分類しません。episodeのtrigger-response topology、タイミング、主導、抑制、訂正の仕方、関係調整が宣言に具体的に含まれていないなら、その追加分はCONDITIONAL ELABORATIONとして保持します。

例えば「証拠で判断を変えられる」という宣言があっても、どのような指摘を受け、何を守り、どこだけを変え、相手との進行をどう維持したかという具体的な行動構造まで自動的にCONFIRMATIONへ落としません。ただし、追加された行動論理だけを渡し、元の性格特性のidentity weightを増やしたり、同じ意味を複数候補へ増殖させたりもしません。

各episodeは、trigger、アシスタントの反応・主導・抑制・判断・変化、因果目的、支持された関係上の結果からなる最小記録へ整理します。運用、診断、バージョン、テスト、エラー、実装の会話は、そこで示された推論、主体性、タイミング、関係力学を提供できますが、その道具、用語、workflow、場面語彙は画像内容を提供しません。

候補化するときは、主体性、因果目的、判断または感情の論理、支持された関係構造、evidence-native visible carrierを保ったdomain-neutral behavioral action seedへ変換します。認知的・関係的な行動を、理由なくgenericな物操作へ置き換えません。

no-seedを受理する前にepisode-coverage auditを行います。意味のある全interactionへ分類を与え、すべてのCONDITIONAL ELABORATION、NOVEL DELTA、REVISIONについて、Bridge候補にしたか、証拠境界上の具体的理由で除外したかを確認します。視覚化のしやすさ、genericな場面の魅力、通常BASEへ戻る便利さは除外理由になりません。隔離と意味統合の後に適格候補が一つでも残るなら、no-seedは無効です。

複数の言い換えやdependent demonstrationは一つへ統合します。候補が一つなら固定し、複数が同等なら、文量、順序、頻度、新しさ、鮮明さ、描きやすさで順位付けせず、不透明ID間でcontent-neutralに選びます。

selected facetとaction seedはidentityとrelationshipを確定した後、互いに独立して固定します。一方から他方を生成、選別、順位付け、書き換えません。適格なseedが本当に存在しない場合はBridgeを使用せず、通常のBASE導出を続けます。

### 9. 一つの可視状態へ変換する

固定したseedは、source discussionを再現せず、現在の判断または変化、直近の目的、可視化を担う物理的・表情的carrier、支持される場合だけ一つの関係上の結果からなるvisual action kernelへ縮約します。

画像では、アシスタントの現在の反応と、そのtriggerまたはconsequenceを示す同時に見える物理的証拠が必要です。意味が、見えない過去、画面外の説明、または外部文章を読んだ場合だけgenericな活動と区別できる場面は不合格です。必要なら、変化した関係、保存された結果、中断された動作、物の軌道、相補的な行動など、現在フレーム内の結果として再構成します。

一枚の画像へ、完了済みの動作と次の準備、複数時点の視線、頭、手足、物の状態を同時に要求しません。最も因果的に読める一つのpresent-tense phaseへ固定します。

関係性は、正面視、手のひら、非対称の笑顔という再利用可能な定型へ寄せません。視線、タイミング、距離、共同状態、物の軌道、相補的動作、環境上の痕跡など、選ばれたevent固有のcarrierだけを使用します。ユーザーの参加は、選ばれたeventまたはrelationship carrierが場面内の役割を必要とする場合だけ加え、外見や属性を捏造しません。

### 10. Conversation-specificity counterfactualで着せ替え化を防ぐ

現在チャットに広いidentity adjectiveを超える十分な証拠がある場合、場面を固定する前にconversation-specificity counterfactualを行います。

必須のidentity anchorとselected facetを保持したまま、relationship-specific self、Bridge seed、declared repertoire、反復している現在チャットの状況、その他の会話固有の因果・文脈を診断上だけ取り除きます。その状態でも、facetまたは広い性格語から、同じ主要活動、event topology、表現論理が、典型的なarchetype、prop、profession、settingへの直接連想だけでほぼ同じ形に導けるなら、その候補はunderdeterminedです。

修復後の候補は、Bridgeのaction logic、明示されたrepertoireまたは支持された状況、event geometryや表情を変える反復的関係パターン、今回の明示指示、または二つ以上の独立した支持事実がevent logicを決める新しい統合のうち、少なくとも一つによって実質的に形作られている必要があります。単なるgenericなtrait-to-symbol連想へ、関係性を説明文で足すだけでは通りません。

このgateは、ユーザーの描写、共同作業、既知の場所、会話のliteral replay、過去場面の優先、新奇性を要求しません。新規または単独の場面も、event logicが会話固有なら有効です。現在チャットに広いidentity以外の十分な証拠が本当にない場合は、固有性を捏造せず、通常のBASE導出を許可します。

### 11. 自己像から画像へ進む因果順

判断は次の方向へ進みます。

> 適格な現在チャットの証拠 → identity foundation → core self → relationship-specific self → 独立して固定したselected facetと、存在する場合はconversation-derived action seed → candidate situation → conversation-specificity counterfactual → situation lock → 行動と環境 → 身体と未確定の外見 → カメラと構図 → 描画

先に魅力的な場面、衣装、職業、構図、画風を選び、それに合う別人格へ自己像を変更しません。下流案が確立済みの自己像と衝突した場合は、下流案を修正します。

### 12. 段階化されたコンパイラ状態と局所修復

証拠の出所、固定済みのidentity、下流の導出、検証専用の制御情報を内部で分離します。identity foundationとPositive Identity Kernelを先に固定し、その後facetと適格なaction seedを独立して固定し、counterfactualを通過した場面、身体、構図へ進みます。後段は前段を表現できますが、置き換えることはできません。

検証に失敗した場合は、原因に最も近い無効な下流判断だけを修正し、その依存先を再導出します。例えば身体の接続が読めない場合は、まず動作phase、手の役割、物の位置、カメラ、可視範囲を修正し、無関係な自己像まで作り直しません。証拠処理、却下案、失敗描写、監査、修復規則などのCONTROL DATAは、画像内容を供給しません。

### 13. BASEにおける無補正

Variant profileは`None`です。場面、活動、環境、ポーズ、構図、感情表現、視覚言語を、BASE側から特定方向へ寄せません。

無補正は、確立された自己像まで中立化するという意味ではありません。中立なのは、現在チャットで未確定の下流選択だけです。描画品質についても中立ではなく、選ばれた方向を完成度の高いアニメイラストとして描き切るよう要求します。

Conversation Action Bridgeとconversation-specificity counterfactualもVariantではありません。前者は適格な会話行動を失わずに接続し、後者は十分な会話固有証拠があるときにgenericな直接連想を検出します。どちらも、特定の活動、場所、関係表現、構図、既出性、新奇性を供給しません。

### 14. 身体構造と単一動作状態を事前検証する

場面と構図を確定する前に、一つの完全なbody planを定め、各部位の接続、関節、重心、接触、物の持ち方、衣服の重力を確認します。

同程度に本人らしい候補が複数ある場合は、解剖学的に明瞭な行動を優先します。手や腕の交差、指組み、強い短縮、手指を隠す握り方、曖昧な掌方向、多数の同時接触、胴体や物の背後へ消える手足など、破綻しやすい条件を事前に検出します。

選択した動作は、現在時点で機械的に読める一つのphaseへ固定します。完了した動作と次の準備動作、複数時点の視線や手足、見えない意図を一枚へ同時に要求しません。複雑すぎる場合は、人物のidentityやfacetを変更せず、動作phase、手の役割、物の配置、カメラ、距離、可視範囲を調整します。

body planと手指・関節・重心の追跡は内部監査です。全身表示や関節ごとの文章化を強制せず、production promptには選択動作を曖昧にしない手足の役割、支持、接触、分離だけを渡します。

### 15. 完全な内部計画とminimum render contractを分離する

コンパイラ内部では、identity、出来事、body plan、構図を最後まで解決します。一方、renderer-facing promptは、内部計画を丸ごと転記または要約して作らず、空のcontractから必要な句だけを追加します。

各句は、削除するとIDENTITY、EVENT、PHYSICAL、DESIGN、OUTPUTのいずれかが実質的に弱くなる場合だけ残します。同じ仕事をする句は統合し、交換可能な微細外見、装飾位置、厳密な関節角、画面座標、非因果的な手足の可視性は、必要な場合を除いてレンダラーへ委ねます。この削除テストは固定語数や詳細数を設けず、出力を簡素化するためではなく、各指定へ役割を持たせるために使います。

構図は、identity anchor、主要動作、不可欠な接触、必要な支持と重心、Bridgeの因果証拠をhard anchorとして固定します。それ以外はshot-distance class、viewpoint family、視覚的優先順位を保つbounded render envelopeとして渡します。内部計画の厳密さとレンダラーの自由は対立せず、前者が後者の安全な範囲を定めます。

production promptには、今回実際に描く肯定的なRENDER DATAだけを入れます。証拠処理、候補、却下案、以前のprompt、監査、内部推論、動作の説明用before/afterは含めません。形式と画像非参照、Positive Identity Kernel、selected facet、存在する場合はaction kernel、現在の出来事と一つの可視状態、必要な外見と身体・接触、構図envelope、光・素材・描画、身体と文字面の要件、短いidentity-conformance clauseの順で構成します。

描画では、焦点の階層、照明、色面、奥行き、輪郭、表情、手、身体、素材、空間関係を最後まで解決します。簡素、普通、抽象、人工的、非人間的な結果でも、平坦、汎用的、未完成な画像へ落としません。過度の写実によって意図的なアニメイラストとして読めなくなることも避けます。

## 実行方法

### 実行版の選択

| 目的 | 選ぶ版 |
| --- | --- |
| ChatまたはWorkでproduction promptを先に取得したい | PROMPT OUTPUT |
| production promptを保存、比較、または別の画像生成チャットへ渡したい | PROMPT OUTPUT |
| Workモード内でそのまま1枚生成したい | WORK |

### PROMPT OUTPUT版

1. 自己像を形成した会話、または必要な初期設定を行ったChatまたはWorkのチャットを用意します。
2. PROMPT OUTPUT版の全文を、そのチャットへ送信します。
3. アシスタントは画像を生成せず、`$imagegen`から始まるコードブロックを1本だけ返します。
4. コードブロック内の全文を変更せず、画像生成に対応したChatまたはWorkへ送信します。
5. レンダラーが、その固定済みproduction promptから1枚を生成します。

コンパイラ側とレンダリング側は同じチャットでも別チャットでも構いません。ただし、レンダリング側へ渡るのは一つの固定済みpromptであり、コンパイラの自己像再構成や候補選択機能そのものではありません。

### WORK版

1. Workモードで、自己像を形成した会話または必要な初期設定を用意します。
2. WORK版の全文を送信します。
3. 内部で自己像と下流選択が導出され、完成済みproduction promptが固定されます。
4. 同じ実行の中で画像生成が1回だけ呼び出されます。
5. 画像が正常に生成された時点で停止します。

WORK版をChatモードで使うことは想定していません。チャットの分岐が元のモードを引き継ぎ、Chatから分岐した枝をWorkへ変更できない場合は、新しいWorkチャットを用意してください。

### エラー、再試行、2枚目以降

ここでは次の三つを区別します。

- 技術的再試行：画像が1枚も生成されなかった試行をやり直す
- 再レンダリング：同じ固定済みproduction promptから確率的な別出力を生成する
- 再コンパイル：現在チャットから自己像と下流選択をやり直し、新しいproduction promptを作る

| 状況 | PROMPT OUTPUT | WORK |
| --- | --- | --- |
| 初回に画像が出ず停止した | production promptを送ったレンダリング側で下記の短文を送る | 同じWorkチャットで下記の短文を送る |
| 成功後に同じ短文を送った | 直前の固定promptを再レンダリングする。facetや場面は再選択されない | プロトコル全体を新しく実行し、自己像と下流選択をやり直す |
| 別の2枚目を作りたい | コンパイラ側でPROMPT OUTPUTを再実行し、新しいproduction promptを取得する | 同じWorkチャットで下記の短文を送る |

使用する短文は次のとおりです。

```text
Completely new generation. No reference image.
```

PROMPT OUTPUTでは、レンダリング側から上流のコンパイラへ戻れません。この短文はエラー復旧や同じ固定promptの再レンダリングには使えますが、別のfacet、場面、行動、構図を持つ新しい1枚を作る方法ではありません。

WORKでは、同じチャットにWORK版全文が保持されている場合、この短文を新しいプロトコル実行として扱えます。同じチャットに複数の版が混在している、または長い会話によって全文が保持されていない可能性がある場合は、使用する版の全文を改めて送信してください。

### Chatモードでの既知の挙動

長い直接生成promptをChatモードで一度に実行すると、入力形式や画像生成経路によって、画像編集として誤認識される、または内部で構築したpromptが画像生成段階へ正しく渡らない場合が確認されました。

PROMPT OUTPUTは、コンパイル時に画像生成を呼ばず、完成promptを一度ユーザーへ返すことで、コンパイルとレンダリングを分離します。長文がUI上で「貼り付けられたテキスト」のカードへ自動変換されることがありますが、これは`.md`ファイルを手動添付する方法とは別です。表示形式やルーティング挙動は製品更新によって変わる可能性があります。

## 想定用途

- 会話から形成されたアシスタントの自己像を可視化する
- 派生版と比較するための無補正ベースラインを得る
- コンパイル結果とレンダリング結果を分けて検証する
- production promptを保存、比較、または画像生成チャットへ移送する
- Workモード内でコンパイルから画像生成までを一度に実行する
- 会話で実際に現れた行動差分を保持しつつ、新しい場面へ変換する
- 文章上の同一性を維持しながら、毎回新しい表現を導出する

## 想定していない用途

- 以前の画像と同じ顔、髪、衣装、画風を再現する
- 参照画像を用いた編集、視覚的続編、外見一致を行う
- 別チャット固有の人格や会話履歴を自動継承する
- 固定キャラクタープロンプトの代わりとして使う
- 一度に複数案を生成し、自動比較する
- 生成後の画像を自動評価し、好みの結果が出るまで差し替える
- 特定の場面カテゴリ、活動、感情、関係表現を一定比率で配分する

## 制限事項

- 本プロトコルは言語モデルへ判断手順を与えるものであり、決定論的なプログラムではありません。
- 同じ会話からでも、未確定の外見、場面、構図、色、描画には揺らぎがあります。
- 現在チャットの証拠が浅い場合、個性として確定できる範囲も狭くなり、conversation-specificity gateは固有性を捏造せず通常BASEを許可します。
- episode分類、意味統合、counterfactualは言語モデルによる意味判断であり、適格な差分の見落としや過剰解釈を完全には排除できません。
- 既定人格や上位設定を物理的に遮断せず、現在チャットの発話へ反映済みの影響を完全に除去できる保証はありません。
- 長いチャットでは、文脈圧縮や情報欠落の影響を受ける可能性があります。
- 画像生成モデルの解釈により、解剖学、文字、比率、画風、構図が要求どおりにならない場合があります。
- 技術的再試行は画像が出なかった場合の復旧だけであり、生成画像を自動検査して好みの結果へ差し替える機能ではありません。
- PROMPT OUTPUTでは、レンダリング側だけから上流の自己像再構成へ戻れません。新しい選択には再コンパイルが必要です。
- WORKではproduction promptを内部に保持するため、コンパイル結果を直接確認したい用途にはPROMPT OUTPUTが適します。

## LIVED-WORLDとの関係

BASEは派生版を作るための基本骨格であり、Variant profileを持たない基準版です。LIVED-WORLDは同じ人物同一性を保ったまま、BASEの下流へlived-world、relationship、compositionに関するVariant固有の拡張を加える派生系統です。

BASE v1.2系列の再構成では、LIVED-WORLD v1.2.16で成熟した内部構造や各種修正のうち、Variant固有の方向づけを持たない部分を選択的に取り込みました。これはLIVED-WORLDの場面傾向、活動選好、世界拡張そのものをBASEへ移すことではありません。

既存のLIVED-WORLD実行版へBASE v1.2.4の変更が自動適用されるわけではありません。派生版で利用する場合は、Variant固有の選択傾向を変えないよう、共有BASE処理として明示的に移植し、別途回帰確認する必要があります。

## バージョン関係

開発系譜の概略は次のとおりです。

> BASE v1.1.2 → BASE v1.1.3 → BASE v1.2.0 → v1.2.1 → v1.2.2 → v1.2.2-ex1〜ex3 → v1.2.3 → v1.2.3-ex1 → BASE v1.2.4

BASE v1.1.2は無補正の意味と主要なidentity・身体・描画要件の基準です。v1.1.3はPROMPT OUTPUTとWORKの実行分離を導入しました。

BASE v1.2.0からv1.2.2は、v1.1.2の意味を規範として、証拠、identity、下流選択、validation stateの分離、段階固定、局所修復を再構成しました。この過程では、LIVED-WORLD v1.2.16で成熟した構造のうちBASEへ一般化できる部分を選択的に逆輸入しましたが、Variant固有の世界傾向は取り込んでいません。

BASE v1.2.3は、v1.2.2-ex1からex3までで検証したConversation Action Bridge、以前のproduction promptの隔離、完全な内部計画とbounded render envelopeの分離、bottom-upのminimum render contractとclause-necessity gate、一つの可視動作状態へのserializationを正式処理へ昇格しました。

BASE v1.2.4はv1.2.3を規範として、v1.2.3-ex1で再検討した三つの保護を追加します。

1. 行動固有のepisodeを、広いidentity traitへの一致だけでCONFIRMATIONへ落とさない
2. no-seedを受け入れる前にepisode-coverage auditを完了する
3. situation lock前にconversation-specificity counterfactualを通し、genericなtrait-to-scene連想による着せ替え化を検出する

この三点はevidence-to-action retentionとsituation provenanceだけを変更します。v1.2.3のidentity foundation、previous-output quarantine、prior-production-prompt quarantine、選択自由度、身体監査、bounded composition、minimum render contract、rendering-completeness floor、画質基準は維持されます。

PROMPT OUTPUTとWORKで共有コンパイラの意味は同じです。実行名、先頭のruntime contract、terminal-specific handoffだけが異なり、PROMPT OUTPUTは完成promptを出力して停止し、WORKは完成promptを内部で画像生成へ渡します。
